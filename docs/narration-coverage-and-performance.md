# Narration coverage and performance plan

Status: research complete, awaiting decision on the phonetic-coverage approach.

## 1. The missing words are not censorship

Kokoro has no word filter. The app uses `sherpa_onnx` 2.0.1, which removed
espeak-ng for licensing reasons. Kokoro's remaining frontend is lexicon-only:
it looks each word up in `lexicon-us-en.txt` and **silently drops** anything it
cannot find. When every token in a sentence is missing, generation returns no
audio and the app raises `SpeechFailure`.

Measured on the imported EPUB (`1794329946640784.epub`, 75,717 words):

- 3.29% of all word occurrences are absent from the bundled US lexicon.
- 12.85% of unique words are absent.
- Names, possessives and inflections dominate: `Reid` (229), `that's` (228),
  `Reid's` (96), `Kit's` (83), `makes` (82), `Walker's` (76), `Grant's` (76),
  `Finn's` (47), `gets`, `wants`, `minutes`, `Derek`, `catches`.
- Curly apostrophes and curly quotes make even dictionary words fail:
  `Derek’s`, `laptop’s`, `“Bro—”` are treated as single unknown tokens.

A/B probe with voice `af_heart` (sid 3), same paragraph:

| Build | Audio | Result |
| --- | --- | --- |
| sherpa-onnx 2.0.1 (current) | 5.39 s | 12 of 27 words silently dropped |
| sherpa-onnx 1.13.8 + espeak-ng | 10.07 s | every word spoken |

Numbers are affected too:

| Text | sherpa 2.0.1 | sherpa 1.13.8 + espeak |
| --- | --- | --- |
| `In 1969, 45% of the 3,200 people paid $12.50 for a ticket.` | 2.97 s (all numbers dropped) | 7.55 s (full sentence) |

Listen to both files in `build/voice-samples/`:

- `current-sherpa-2.0.1.wav`
- `espeak-sherpa-1.13.8.wav`

## 2. Why this happened

`sherpa-onnx` v2 removed espeak-ng because GPL-3.0 is incompatible with its
Apache-2.0 license (k2-fsa/sherpa-onnx#3731). The replacement is a lexicon file;
OOV handling is the app's responsibility (k2-fsa/sherpa-onnx#4139). Misaki's
gold/silver lexicons are exception dictionaries, not complete dictionaries:
regular inflections are generated by misaki's rules at runtime, and v2 has no
rules.

The bundled `lexicon-us-en.txt` is that exception dictionary (178,401 entries).
It contains `make`, `watch`, `watching`, but not `makes`, `notices`, `noticed`,
`elbows`, `betrayed`, `relocated`, `suggested`, `tries`.

## 3. Options for full coverage

### Option A — sherpa-onnx 1.13.8 + espeak-ng-data (recommended for the pilot)

- Downgrade `sherpa_onnx` to `^1.13.2` (resolves 1.13.8, still has espeak-ng).
- Bundle a trimmed `espeak-ng-data` (812 KB: `en_dict`, `phondata`, `phonindex`,
  `phontab`, `intonations`, `lang/gmw/en`, `lang/gmw/en-US`).
- Pass `dataDir`; espeak phonemizes the whole text, so nothing is dropped.
- Preserve US/UK voices by passing `extra: {'lang': 'en-us' | 'en-gb'}` per
  utterance (voices 20–27 are UK).
- The speaker timbre is unchanged, but every pronunciation now comes from
  espeak rather than the misaki gold lexicon. That is the quality trade to
  evaluate with the two samples.
- Pros: complete text, numbers/dates/currency, names, slang, profanity; no
  per-book preprocessing; same Kokoro voices.
- Cons: GPL-3.0 obligations if the app is distributed; 1.13.x is older.
  For a private pilot this is acceptable, but it must be revisited before a
  public/closed-source release.

### Option B — stay on 2.0.1 and supply a G2P (GPL-free)

Two sub-options, both keep Apache-2.0:

1. Ship a much larger lexicon generated offline (CMUDict + misaki rules +
   inflections + names) and accept rare OOV.
2. Port/use a permissive G2P at runtime and pass pre-phonemized tokens through
   `OfflineTtsGenerationConfig.phonemeCodepoints` or `.tokens`.

`phonemize` 1.0.0 (MIT, pure Dart) is a candidate for (2): rule-based English
G2P, POS/homograph handling, number expansion. Its IPA needs a mapping layer to
Kokoro's token set (`oʊ` → `o ʊ` or `O`, `ɝ` → `ɜ ɹ`, etc.) and quality must be
verified. This is the clean long-term path, but it is a larger project and
still needs lexicon-first handling for heteronyms.

### Option C — different TTS engine

Pocket TTS and Supertonic have built-in frontends and never drop words, but
switching engines changes the voice identity and cast. Not recommended now.

## 4. Performance findings

Benchmarks on this M1 (machine was busy; treat as relative numbers), Kokoro
int8, five sentences per round, after warm-up:

| Threads | RTF |
| --- | --- |
| 1 | 1.83 |
| 2 | 1.27 |
| 3 | 1.24 |
| 4 | 1.20 |
| 6 | 1.36 |

Two threads are within ~6% of four threads while using half the cores. That
confirms Battery saver's 2-thread choice as the right default on phones. Four
threads only help when latency matters and power does not.

Already implemented: warm worker reuse, 30/90 s idle unload, pause-aware clip
generation, 2/4 clip prefetch, cached model directory, LFM3-Audio idle unload,
and avoiding PDF body rebuilds.

Next performance work, in order of expected impact:

1. **Synthesized-clip cache per passage.** Re-reading a page or moving back and
   forth currently re-synthesizes everything. A small disk LRU (e.g. 100–200 MB)
   keyed by book + section + sentence + voice settings removes that work.
2. **Low-power narration mode.** A toggle that uses the System engine
   (`AVSpeechSynthesizer`) for long sessions. This is the largest battery win
   available and already fits the existing `VoiceEngine.system` path.
3. **On-device profiling before tuning prefetch.** Run a release build on the
   iPhone, measure RTF and queue depth at 2 threads / 2 clips; raise prefetch
   only if the queue starves.
4. **Streaming playback (later).** `generateWithCallback` plus a streaming
   `just_audio` source would remove per-sentence WAV writes and inter-clip gaps.
5. **Model lifetime.** Keep the current 30 s battery-saver unload; consider
   30 s on iOS and 90 s elsewhere.

## 5. Reliability fixes independent of the model choice

These should land regardless of A/B/C:

1. **Normalize text before synthesis.** Curly quotes/apostrophes → ASCII,
   em/en dash → comma or space, ellipsis → `...`, collapse whitespace, strip
   zero-width characters. This alone recovers `Derek's`, `laptop's`, `“Bro—”`
   as separate words in v2.
2. **Never abort a section for one bad fragment.** If a sentence yields no
   audio or throws, split it at punctuation/words and retry; skip only the
   unrenderable piece. Current code stops the whole run on one `SpeechFailure`.
3. **Expand numbers/dates/currency** if v2 is kept; espeak handles them in
   Option A.
4. **Surface failures once**, not per sentence, and keep the highlight in sync
   when a piece is skipped.

## 6. Recommended sequence

1. Listen to the two samples and choose the voice/phoneme direction.
2. Land the text-normalization and retry fixes (small, no dependency change).
3. If the espeak sample is acceptable: adopt Option A, bump to 1.13.8, bundle
   `espeak-ng-data`, pass `dataDir` and per-speaker `lang`, and verify macOS
   then iPhone. Document the GPL status.
4. If espeak quality is not acceptable: keep 2.0.1, build the complete lexicon
   and/or prototype `phonemize` → `phonemeCodepoints`, then validate on the same
   paragraph and EPUB.
5. Add the clip cache and the low-power System mode; profile on the iPhone.
6. Re-run `flutter analyze`, unit/widget tests, the Kokoro cast and
   sentence-highlight integration tests, and a physical-device narration test.

## 7. Validation checklist

- Same paragraph produces all 28 words, including `makes`, `minutes`,
  `notices`, `Derek's`, `laptop's`, `“Bro—”`, `Usman`, `relocated`.
- Numbers/dates/currency are spoken.
- US and UK voices keep their dialect.
- No `SpeechFailure` on a sentence containing only punctuation or an unknown
  word.
- Highlight and Now Playing stay in sync through skipped/failed fragments.
- iPhone: no stutter with Battery saver; measure RTF, battery and memory.
- `flutter analyze`, `flutter test`, and focused integration tests pass.
